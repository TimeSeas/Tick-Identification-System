# 毕业设计系统规划：基于深度学习的蜱虫与叮咬伤口智能识别系统

> 面向自主完成 · 2026-09-03 改版 · 本科毕业设计（常规周期，按 16 周规划）
> 原则：本仓库代码**由你亲手扩展**，本文档只告诉你做什么、怎么做、做到什么算完成。
> **当前重点（2026-09-04 用户确认）：蜱种分类优先**——先 WP1 清洗（3 大媒介种先行，31 种扩展）+ WP2 分类模型；WP3 伤口分割与 WP4 多类别后置。训练子集：31 物种 ≥50 张/类（共 6171 张），清单见 `data/tick_species/物种中文名对照表.csv`。

## 1. 选题与定位

**选题名称**：基于深度学习的蜱虫与叮咬伤口智能识别系统

**系统做什么**（一句话）：用户上传一张照片，系统回答四件事——**图上有没有蜱虫（以及是什么昆虫）、是什么蜱种、皮肤上有没有叮咬伤口（在哪里、多大）、风险建议是什么**。

**成果形态**：以 Web 应用为主（桌面 GUI 可选加分），算法训练为底层原理，可选软硬件结合边缘部署。

**为什么值得做**（论文绪论素材）：
- 蜱虫传播莱姆病、落基山斑疹热等人畜共患病；**蜱种是疾病风险的决定因素**（黑腿蜱→莱姆病、孤星蜱→α-gal 综合征、犬蜱→落基山斑疹热）
- 被叮咬后的**皮肤红肿伤口**是就医判断的直接依据，现有研究少有"蜱种识别 + 伤口分割"一体化的系统
- 户外场景误把其他昆虫当成蜱虫的误报问题真实存在——用多类别检测把"其他昆虫"建模为真实类别来抑制误检，是可量化的工程贡献

**四个创新点**（答辩与论文核心）：
1. **SAM 辅助标注方法学**（已有实证：主数据集 1649 条标注 0 失败；材料见 `论文研究材料/SAM自动标注原理与效果分析.md`）
2. **检测→蜱种→伤口分割的多模型协同系统**（三模型级联，端到端输出风险评估卡片）
3. **多类别检测的误检率抑制**（单类 vs 多类对比实验，量化误检率下降幅度）
4. **TickIDNet 分物种置信阈值方法的复现与改进**（不同蜱种分类难度不同，设置不同决策阈值）

## 2. 总体架构（四层）

```
┌──────────────────────────────────────────────────────────────┐
│ 展示层   Web 应用（主）：上传图片 → 报告卡片（虫种/蜱种/伤口/建议）│
│          桌面 GUI（可选加分）                                  │
├──────────────────────────────────────────────────────────────┤
│ 服务层   FastAPI：模型编排、级联推理、结果 JSON                 │
├──────────────────────────────────────────────────────────────┤
│ 算法层   三个模型：                                            │
│   M1 多类别昆虫检测（Mask R-CNN）：蜱/螨/农田昆虫，降误检       │
│   M2 蜱种精细分类（ResNet-50 三分类，检测框 ROI 级联）         │
│   M3 叮咬伤口分割（Mask R-CNN，tick-bite 数据集）              │
├──────────────────────────────────────────────────────────────┤
│ 边缘层   ONNX 导出 + INT8 量化 + onnxruntime（可选）            │
└──────────────────────────────────────────────────────────────┘
```

**级联推理链路**：上传图片 → M1 检测 → 输出"这是一只蚜虫（非蜱虫）"或"检测到蜱虫 ×N" → 蜱虫框 ROI 裁剪 → M2 蜱种分类（3 种 + 置信阈值）→ 若图中含皮肤 → M3 分割叮咬红肿区域 → 汇总输出风险卡片（蜱种、置信度、伤口位置与面积、就医建议）。

## 4. 工作包（WBS）与时间线

> 每周 8-10 小时投入估算。每个 WP 含「做什么 / 怎么做 / 产出 / 完成标准」。

### WP1 蜱种数据准备（第 1-3 周）

**做什么**：建立 M2 蜱种分类数据集（3 类：Ixodes scapularis 黑腿蜱 / Amblyomma americanum 孤星蜱 / Dermacentor variabilis 犬蜱）。

**怎么做**：
1. 先导：解析本地 75 张样例文件名（格式 `Genus_species_sex_lifestage_source_alive_feedstage_#.jpg`）得到物种标签，按物种归档；
2. 扩展：从 iNaturalist 按 3 个物种检索收集图片（TickIDNet README 的 3 个 GBIF DOI 是合法出处，论文中引用），每类目标 200+ 张；
3. 数据清洗：剔除含多虫/标签不明/来源重复的图；记录每类数量与来源。

**产出**：`data/tick_species/{ixodes_scapularis, amblyomma_americanum, dermacentor_variabilis}/`。

**完成标准**：每类 ≥150 张可用图；若收集量不足，降级方案：75 张 + 强数据增强 + 5 折交叉验证的小样本方法学（本身可写论文）。

### WP2 蜱种分类模型（第 3-5 周）

**做什么**：训练 3 类蜱种分类器（ResNet-50，ImageNet 预训练微调）。

**怎么做**：
1. 5 折交叉验证（小样本场景的标准做法，论文方法学）；
2. 复现 TickIDNet 的**分物种置信阈值**方法：参考 `TickIDNet/Confidence Thresholds/confidence_thresholding.py` 与 3 个物种 CSV（每个物种有自己的决策阈值），在验证集上网格搜索阈值并对比"统一阈值 vs 分物种阈值"；
3. 附加实验（可选）：文件名同时编码了 fed/unfed，可顺带训练饱血二分类作为对比实验；
4. 评估：accuracy、F1、混淆矩阵、ROC-AUC。

**产出**：`output/tick_species_classifier.pth` + 阈值文件 + 实验记录。

**完成标准**：test accuracy ≥0.85（若数据不足则 ≥0.80 + 交叉验证报告）。

### WP3 叮咬伤口分割（第 2-5 周）

**做什么**：用 tick-bite 数据集训练伤口分割模型（Mask R-CNN）。

**怎么做**：
1. 数据清理：categories 去掉 id=0 冗余项（参考主数据集 SAM 补全时的清理方法）；统计标注面积分布，超大全图级标注（接近 640×640 的）人工复核决定保留或剔除；
2. 训练：复用 `src/train/train_torchvision.py` 训练管线（改数据路径为 tick-bite 三个 split 即可，多边形齐全无需 SAM）；
3. 评估：`src/eval/evaluate_model.py` 出 mAP；抽查预览图确认分割贴合红肿区域；
4. **域差异实验（论文亮点）**：现有蜱虫检测模型（特写训练）直接在 tick-bite 皮肤图上推理，评估其泛化性——若差，讨论特写 vs 皮肤场景的域差异，必要时在 tick-bite 图上补标虫体框再训练。

**产出**：`output/mask_rcnn_tick_bite.pth` + mAP 报告 + 域差异实验记录。

**完成标准**：伤口分割 mAP@0.50 ≥0.60；域差异实验有明确结论。

### WP4 多类别昆虫检测（第 5-9 周）

**做什么**：M1 从单类蜱虫检测升级为多类别（蜱/螨/农田昆虫），量化误检率下降。

**怎么做**：
1. 复核 `output/sam_pilot/review/` 的 7 类 210 张预标注（X-AnyLabeling 修正），通过后 `scripts/sam_auto_label.py --per-class 0` 扩量（断点续跑）；
2. 修改 `train_torchvision.py` 支持多类别（你自主改，要点：`NUM_CLASSES`=类别数+1；folder→id 映射；`setup_multi_class_config()` 补真实逻辑；数据集从扩量 COCO JSON 读取）；
3. 对比实验：单类模型 vs 多类模型在 archive3 四类农田昆虫上的误检率（复用 `test_false_positives.py` 指标口径），量化"误检率从 X% 降到 Y%"；
4. 训练技巧：类别不平衡（蜱虫 1602 vs 各昆虫类数百张）→ 加权采样或损失加权，做消融。

**产出**：多类别模型 + 误检率对比表。

**完成标准**：蜱虫 mAP 不低于单类模型 -5%，其他昆虫误检率下降 ≥50%。

### WP5 三模型级联集成（第 9-10 周）

**做什么**：把 M1→M2→M3 串成一条推理管线，输出结构化风险评估卡片。

**怎么做**：
1. 新写 `detect_tick_system.py`（复用 `detect.py` 的模型加载代码）：M1 检测 → 逐蜱虫框裁剪 → M2 蜱种+置信阈值 → M3 伤口分割（同图）→ 汇总 JSON；
2. 风险规则：蜱种 + 伤口面积 → 建议文案（规则表写死，论文里说明规则依据文献）；
3. 端到端评估：构造 30-50 张含蜱+伤口的测试样例（tick-bite 图 + 主数据集图组合），人工核对链路正确率。

**产出**：`detect_tick_system.py` + 端到端评估记录。

**完成标准**：链路端到端正确率与各模型单独指标乘积差距 <5%。

### WP6 Web 应用（第 10-13 周，主展示）

**做什么**：FastAPI + 前端页面：上传图片 → 报告卡片。

**怎么做**：
1. 后端：`POST /analyze` 接口（调 WP5 管线，返回 JSON：昆虫类别/蜱种/伤口多边形/风险建议）+ 结果图 base64；模型常驻内存；
2. 前端：单页 HTML+JS（文件选择 → 结果卡片 + 标注可视化），不追求美观，答辩可演示即可；
3. 论文素材：系统界面截图、接口文档、响应时间记录。

**产出**：`web/` 目录（app.py + templates + static）。

**完成标准**：浏览器上传测试图 5 秒内返回完整报告卡片。

### WP7 桌面 GUI（第 12-14 周，可选加分）

**做什么**：PyQt5 桌面版（选图/摄像头实时），封装 WP5 管线。

**怎么做**：主窗口 + QThread 后台推理 + 摄像头抽帧；`pyinstaller` 打包。时间不足可跳过。

**产出**：`gui/` 目录 + 可执行文件。

**完成标准**：现场可演示实时识别。

### WP8 边缘部署（第 13-15 周，可选）

**做什么**：ONNX 量化部署。**分类模型先行**（ResNet 蜱种分类导出 ONNX 无动态控制流，一定能跑通）；伤口/检测的 Mask R-CNN 导出有 RPN/NMS 动态控制流难点（对策同前：TorchScript 或 YOLOv8m 替代对比）。设备：树莓派 5 或 PC+摄像头演示边缘形态。性能对比表（RTX 4060 / CPU / 边缘）写论文。
