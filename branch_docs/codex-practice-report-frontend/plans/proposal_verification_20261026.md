# 保留候选框的检测复核实验

状态：2026-10-26本轮已完成。逐框复核未采用，后续微调+.3门槛通过完整开发和来源核验后成为分支默认；有效run02及HTTP run04见[实验登记](../experiments/detector_calibration_run01.md)。保留以下设计及失败演进，不把未采用方案视为当前架构。

动机：v3微调第2轮完整开发级联误报79→22、MAE .20745→.15426，但109张回顾图蜱虫53/55→51/55；486张物种图检出483→470。正确物种候选441→446、正确确认322→334，仍不能忽略漏检代价。原默认暂不替换。

方案：原v3负责候选框，新微调模型只运行backbone和ROI分类头，在同一整图特征上复核每个原框。坐标经过新模型transform同步缩放，不把原图框直接交给缩放特征；新模型自身tick softmax≥.5才接受，不比较两个模型分数。不使用新的RPN，所以可以单独检验漏检是否来自proposal丢失。框保留原定位，按新ROI分数做IoU=.3去重；全图/空检出切块仍由原服务流程控制。

使用已冻结第2轮，不新增训练、不改原图片/权重、不对80补充物种调参。先109回顾用于架构诊断，再完整495开发val与486图片级物种检查；三者共同判断。若失败保留失败，不提升默认。通过后冻结全部两模型身份和配置，再检查80补充正例并做独立数据库HTTP。该方案多一次backbone，必须实测时间，不承诺速度提升。分类候选只由旧28类物种模型给出，不能宣称新模型解决未知物种。

实现前先写坐标缩放、空候选、阈值及去重测试。新模块独立于原Detector，原始比较与配置保留。完整结果、代码SHA与模型SHA登记在实验文档。

## 逐框复核结果及后续校准

109回顾复核检出仍51/55，螨误报8/54，未恢复召回，停止该架构，不进入默认。只读审查未见P1/P2，58项回归通过；保留复现实验模块，不在main启用。

新模型在.5门槛下显著减少误报，下一项受控候选为单独测试.3检测门槛（不是继续训练、不是修改物种阈值）。先完整495开发val，仅drop_in原规则；仍执行原召回/计数/误报三硬门槛，不能只按109回顾结果选。该候选使用重训模型而非原模型单纯降阈值；不同模型的分数不视作已校准的同一概率。通过后冻结profile，再检查486和109的来源代价，80补充正例仍不用于选择。

首次det03_run01离线缓存仍硬编码.5，导致报告既不是完整.3也不是标准.5（切块触发已变），判定无效、不得用于选模。原配置configs/inference_detector_finetune_det03.json撤回，不作为部署入口。其486实模型图片级输出仍可作.3开发诊断，但不能补成完整检测评估。补充CachedDetector门槛回归后在det03_run02重跑，允许复用相同输入SHA的原生检测缓存，不复用错误级联trace。profile构建器拒绝缺少阈值感知缓存源码身份的非默认阈值报告。
