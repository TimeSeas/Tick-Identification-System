## 版本和原文隔离

- 本分支的需求、设计、实验、运行说明和agent上下文只在本目录维护。原项目README、docs及论文/毕业设计材料保留原用途；根文件只作必要路由，不追加分支实验结果。
- `baseline/`和日期历史目录保存已有版本，不将其重写为新实验结果。发现旧结论不适用，在当前上下文及历史索引标注原因。
- 当前冻结profile采用.gitattributes的-text保留精确字节；Git文本换行转换也会改变SHA，修改后必须重新绑定身份，不能静默沿用冻结报告。源码SHA以实际运行时磁盘字节为准，变化后不静默恢复训练。
- 每个阶段有明确源提交、数据/配置/权重SHA256、实验目录和状态。原权重、原图片、原划分及数据库不覆盖；训练输出不放进源码或Git。
- 用户其他未提交修改保持原状。提交时逐路径检查，不能把任务书个人信息、数据库、模型和大体积数据一起暂存。

## 工作开始与交接

1. 确认当前Git分支，阅读README、CONTEXT、当前计划和最近历史事件；不要只凭旧聊天摘要操作。
2. 实现前更新计划和实验登记，明确成功条件与未解决问题。并行工作必须注明文件归属；同一GPU只运行一个训练/评估任务。
3. 数据先按全部任务的SHA、来源照片与观测分组，冲突标签隔离，不根据模型预测擅自改人工类别。验证/校准/验收不能进入训练，旧测试不能反复用来挑参数。
4. 每轮更改后更新CONTEXT中的已完成、进行中、下一步、阻塞及实际命令；新增决策和失败追加HISTORY，实验结果更新登记。记录失败原因，不默默删掉失败实验。
5. 交接记录训练是否仍在运行、PID/日志/检查点和恢复方式。写入“已训练”“已部署”“通过验收”前必须有对应证据；后台任务已启动不等于完成。

同时报告蜱虫召回、非蜱虫误报、计数和蜱种正确率。明确标注组件/级联、历史/新划分、人工真值/来源代理、完整/部分运行。样本展示使用冻结名单，既展示改善也展示失败；降低阈值、减少类别、拒绝全部样本或修改文案不能代替模型提升。
