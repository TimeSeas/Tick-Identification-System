本任务在用户授权的 `codex/practice-report-frontend` 分支由Codex等智能体开发，主分支不修改。当前推理优化已实现并接入后端配置；此文记录其离线验收，不涉及实践报告或Web数据库。

`scripts/evaluate_optimized_cascade.py`不训练模型、不选择阈值。旧策略来自本地 `output/optimization_20261015/baseline_app/services/pipeline.py`；新策略来自当前后端及 `configs/inference_optimization.json`。两者共用检测候选缓存和分类权重、依次运行，避免显存重复占用。

## 运行与复现

在仓库根目录、已安装的 `tick_detection` 环境下执行：

```powershell
# 先确认对应集合检测缓存已完整完成
python scripts/evaluate_optimized_cascade.py --subset val
# 验证选择并冻结后运行；不按测试结果继续调参
python scripts/evaluate_optimized_cascade.py --subset test
# 流程检查，不能当完整结论
python scripts/evaluate_optimized_cascade.py --subset val --limit 2
```

完整缓存须包含valid 332张或test 134张COCO图，以及各集合预先确定的135张非tick类别代理。GPU检测不再重复运行：分数≥0.5、快照IoU=0.3去重、全图空结果才切块。分类仍使用可用GPU，请勿与其他GPU任务并发。

旧分类使用中心裁剪及历史CSV阈值；新分类使用配置中的双视图、15%上下文、单候选50%原图融合和匹配阈值。多候选使用各自区域及区域阈值；拒绝规则逐框运行，各模型分数不直接排序比较。评估中文映射留空，不影响定位和确认状态。复现需要本地基线快照、数据、权重和清单，仅克隆代码不足以重现。

## 产物、完整性与续跑

原始产物位于Git忽略的 `output/optimization_20261015/`，不随代码推送：

- `cascade_val_baseline.json` / `cascade_val_optimized.json`：逐图返回值、耗时、定位匹配和数量误差；测试文件将val替换为test。
- `cascade_val_summary.json` / `cascade_test_summary.json`：最终汇总及数据、源码指纹，均标记 `partial=false`、`complete_for_cache=true`。验证467图、测试269图均完整。
- `cascade_*_predictions.json`：分类预测缓存，按权重、视图、输入大小、RGB内容、原图内容和融合权重区分；分类实现变化使缓存失效。
- `frozen_cascade_selection.json`：测试前冻结的配置与验证签名。

每20图及正常/异常退出保存；同命令重跑跳过完成图片。源码、配置、权重或检测缓存改变时，逐图结果拒绝混用，应先另存归档。`--limit N`产物带 `_limitN` 后缀，仅用于局部流程检查。

模型权重、划分和相关推理源码指纹记录于汇总manifest。应用启动另行验证配置、类别、尺寸及分类权重/划分哈希，防止把旧校准误配新模型。数据库、原始图片和模型不随代码推送；评估不写Web历史记录。

## 指标边界与运行验证

COCO采用检测分数降序、IoU≥0.5一对一匹配，报告TP、FP、FN、精确率、召回率和逐图数量MAE。分母为零时保存null。确认框和待确认框都算检出，另报数量；COCO无逐框蜱种标签，所以确认框数量不等于正确蜱种数。

135张其他类别图只有文件夹整图标签，未经逐框人工核验，属于负样本代理；检出图数单独报告，不并入COCO精确率。478张单候选蜱种独测的区域标签也继承整图，不能视为独立框级真值。风险建议文案不在评估范围。

耗时包含读取、解码和分类，排除了GPU检测且受缓存命中影响，不能作为端到端加速证据。后端14项回归、前端类型检查和生产构建通过；回归包含并发请求串行进入共享模型、图片方向/边界及校准产物一致性。推理锁仅在单进程有效，多工作进程仍可能同时占用GPU。页面运行及服务重启验收应另行记录，不能用离线测试替代。
