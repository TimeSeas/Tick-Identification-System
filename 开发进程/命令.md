# 日常开发命令速查

> 基于Mask R-CNN的蜱虫识别系统的设计与实现 · 从环境激活到部署运维的全部常用命令
> 环境约定：conda 环境 `tick_detection`（PyTorch/模型）；Node 22（前端）；Docker Desktop（部署）
> 终端约定：Git Bash 命令与 PowerShell 通用；**PowerShell 里 curl 是别名，必须写 `curl.exe`**

---

## 1. 环境与 GPU

```bash
conda activate tick_detection          # 激活项目环境（训练/推理/后端都要）
nvidia-smi                             # 看 GPU 占用（长任务前先查有没有别人占卡）
node --version && npm --version        # 确认前端环境
tasklist | grep python                 # 看有哪些 python 进程在跑（排查僵尸进程）
```

## 2. 训练与模型（项目根目录执行）

```bash
# 蜱虫检测（单类 Mask R-CNN）
python src/train/train_torchvision.py

# 蜱种分类：3 类基线 / 31 类通用版（改脚本顶部常量切换消融实验）
python src/train/train_tick_species.py
python src/train/train_tick_species_all.py

# 划分数据集（--min-per-class 50 → 31 类；--max-per-class 压长尾）
python scripts/split_species.py --min-per-class 50 --out data/tick_species/split_31cls.json

# 分物种置信阈值（输入验证集预测 CSV）
python scripts/confidence_thresholds.py --results 结果.csv --out output/thresholds.csv
```

## 9. Docker（部署与容器）

```bash
cd web
docker compose build                        # 构建镜像（改代码后）
docker compose up -d                        # 启动全部（-d 后台）
docker compose up -d --build                # 重建并启动（改后端代码用这个）
docker compose ps                           # 查看容器状态（Up/healthy 正常）
docker compose logs -f backend              # 跟踪后端日志（-f 实时）
docker compose exec backend python -c "..." # 进容器执行命令
docker compose restart backend              # 重启后端（只换模型文件时用这个）
docker compose stop backend                 # 停止（不删容器不删数据）
docker compose down                         # 停并删容器（数据卷还在）
docker compose down -v                      # ⚠️ 连数据卷一起删（清空历史库！）
docker images                               # 镜像列表
docker volume ls                            # 卷列表（web_dbdata = 历史库）
docker system df                            # 磁盘占用
```

**坑备忘**：
- Docker 命令报 `cannot connect to the docker daemon` → Docker Desktop 没启动，手动打开等鲸鱼变绿
- `docker compose exec backend ls /usr/...` 被 Git Bash 转义成 Windows 路径 → 命令前加 `MSYS_NO_PATHCONV=1`
- `docker compose build | tail` 会吞掉失败退出码 → 判断成败看输出内容或 `docker images`

## 10. 数据库（SQLite）

```bash
# 本地开发库（web/backend/data.db）
python -c "import sqlite3; [print(r) for r in sqlite3.connect('web/backend/data.db').execute('SELECT id,filename,created_at FROM analysis_records ORDER BY id DESC')]"

# 容器库（Docker 卷 web_dbdata，容器内 /app/db/data.db）
cd web && MSYS_NO_PATHCONV=1 docker compose exec backend python -c "import sqlite3; [print(r) for r in sqlite3.connect('/app/db/data.db').execute('SELECT id,filename FROM analysis_records ORDER BY id DESC')]"

# 清空本地库：直接删文件（后端重启后自动重建表）
rm web/backend/data.db
```

## 11. 进程与端口（Windows）

```bash
netstat -ano | findstr :8000              # 查谁占了 8000 端口（最后一列是 PID）
taskkill //PID <PID> //F                  # 杀掉占用进程
# PowerShell 等价：Get-NetTCPConnection -LocalPort 8000 | Select OwningProcess
```

## 12. 快速排查顺序（后端有问题时）

```
1. 后端日志：uvicorn 终端 / docker compose logs backend
2. 健康检查：curl localhost:8000/healthz
3. 接口文档：浏览器 /docs 手动试一次
4. GPU/进程：nvidia-smi + tasklist | grep python
5. 前端 Network：F12 看请求状态码与响应
```
