## 一句话项目描述

**基于Mask R-CNN的蜱虫识别系统的设计与实现**：上传照片，检测优先级联自动完成蜱虫逐只定位与数量统计（全图+切块补偿）、蜱种细粒度分类（28 物种）、分物种置信阈值决策（低置信输出"存疑"），非蜱虫给出昆虫兜底识别，含三层误检防御，提供 Web 界面与 Docker 一键部署；部件级实例分割为深化方向。

## 简历条目（2026-10-14 定位收敛版：聚焦识别，可直接粘贴）

**基于Mask R-CNN的蜱虫识别系统的设计与实现** · 个人项目 · 2026/04 - 至今

技术栈：Python、PyTorch、Mask R-CNN、ResNet-50、SAM、FastAPI、SQLAlchemy、SQLite、Vue3、TypeScript、Element Plus、Docker Compose

项目介绍：面向蜱虫识别的图像识别系统：上传照片即输出图内蜱虫数量与逐只定位、蜱种鉴定（低置信输出"存疑"）；非蜱虫照片给出"疑似什么昆虫"的兜底识别。检测-分类级联推理 + 三层误检防御，Web 端 Docker 一键部署；部件级实例分割为深化方向。

个人职责：
- 数据管线：三源合并构建 173 蜱种、8055 张图像数据集（GBIF API / iNaturalist / HuggingFace），YOLOv8 辅助预标注 + SAM 自动标注管线提速；再用检测模型辅助清洗，剔除 189 张零检出噪声、保留多虫/小目标难样本；以人工框为提示零失败生成 1649 条分割掩码，box 提示与无提示 AMG 的对比分析成为论文创新点
- 模型效果：Mask R-CNN 蜱虫检测 mAP@0.50 达 0.866（三轮迭代 0.842→0.845→0.866，1024 分辨率 + 579 张小目标补标）；ResNet-50 蜱种 28 类细粒度分类 test F1 0.74（数据清洗 + 448 分辨率消融，同测试集 +8.3 点）；28 类昆虫粗分类 acc 94.25%（零标注成本，文件夹即类别）
- 决策机制与架构：复现分物种置信阈值方法（Villon et al. 2020），低于阈值输出"存疑"而非硬判，落地"宁可不答、不要猜错"的可靠性优先决策；设计检测优先级联（全图检测→切块补偿→细分类→粗分类兜底）与三层误检防御（大框否决/第二意见复判/螨类否决），实测非蜱虫误报全拦、真蜱虫 0 误伤
- 系统与排障：独立设计 FastAPI + Vue3 + TypeScript 前后端分离系统（模型常驻内存、统一响应协议、SQLite 历史记录），Docker Compose 双容器一键部署；定位并修复 train-serve skew（transform 分辨率不随权重保存导致评估/推理静默降级）与重复检出嵌套框两个隐蔽 bug

> ① YOLO 角色从"负责目标检测"改为"辅助预标注"（真实检测模型是 Mask R-CNN）
> ② "ResNet 蜱/非蜱二分类" → 28 物种细粒度分类 + 28 类昆虫粗分类兜底
> ③ "把蜱体、盾板、足等部件单独提取" → 现为**深化方向**（当前只有整只蜱虫实例掩码；部件级需先做部件标注与多类训练，已列入后续实验，切勿写成"已实现"）

## STAR 故事（行为面试题对应）

**S（情境）**：毕业设计需从零构建"检测+分类+系统"的完整 AI 应用。
**T（任务）**：自主完成数据集、模型训练、Web 系统与部署。
**A（行动）**：
1. 数据卡点——TickIDNet 官方数据仅含元数据无图片：从 README 的 3 个 GBIF DOI 溯源，另辟 GBIF API 免登录采集路径；遭遇 static.inaturalist.org 403，定位并切换官方 Open Data S3 镜像
2. 训练卡点——主数据集标注全空无法训练 mask 头：用 SAM 以人工框为提示生成 1649 条多边形，同时产出"box 提示 vs AMG"的方法学对比（成为论文创新点）
3. 长尾难题——31 类样本量 50~1325 严重失衡：加权采样 + 标签平滑 + 压平长尾 + 448 分辨率逐项消融
4. 数据质量难题（核心）——31 类模型大量样本被阈值判"不确定"，定位根因为训练集噪声：设计"检测模型辅助清洗"方案，**只剔除真噪声（非蜱图）、保留难样本（多虫图/小目标图以保证系统对非标准上传的健壮性）**，并识别出"整图训练 vs 裁剪推理"的分布不一致问题，规划 ROI 训练方案
5. 级联误判难题（核心）——上线实测两类致命问题：真蜱虫被判成昆虫（粗分类第一闸误判）、大蜱虫被切块切碎：推倒重排为**检测优先级联**，再用实测数据设计三层误检防御（蚜虫群高分误检但全图粗分类判 aphid 92-97% → 大框否决；叶螨 3 框误检 → 螨类否决），真蜱虫 Top15 大框图 0 误伤
6. 部署卡点——容器内中文字体缺失致标注乱码、torch 缓存重复下载、卷路径错层：逐一定位修复并沉淀部署文档
**R（结果）**：检测 mAP@0.50 0.866；28 类蜱种 F1 0.742；3 分类超论文基线；级联 8 图回归全过；Web 系统 Docker 一键交付；全程自主完成（含前端从零学习 Vue3/TS）。

## 高频面试题预答

| 问题 | 回答要点 |
|------|---------|
| 为什么用级联而不是一个多任务模型？ | 三类数据标签体系不重叠无法统一训练；级联可独立迭代、可解释、部署分层；且细粒度识别用检测先定位再分类是标准范式 |
| 怎么保证"绝不把蜱虫报成其他昆虫"？ | 检测优先级联（判别力最强的检测模型做第一道闸，粗分类降级为兜底）+ 三层误检防御（大框否决/第二意见复判/螨类否决），否决规则只在高置信触发、蛛形纲互不否决，实测真蜱虫 0 误伤 |
| 细粒度分类怎么提精度？ | 高分输入（448）、领域预训练（iNat）、长尾加权、标签平滑——消融表实证（+8.3 F1） |
| SAM 是标注工具还是系统组件？ | 标注工具（教师）：预标注→人工复核→训练专用模型；系统推理用训练模型（毫秒级 vs SAM 9.5s/张） |
| 模型怎么部署？ | FastAPI 常驻内存 + Docker Compose（nginx 反代 + uvicorn），模型/数据只读挂载热更新，健康检查+自动重启 |
| 数据从哪来？ | 公开生态数据（GBIF/iNaturalist/HF，CC 许可）+ SAM 自建标注，全部有溯源清单 |
| 训练和推理分辨率不一致的坑？ | torchvision transform 的 min_size/max_size 不随 state_dict 保存，重建模型默认回 800；评估必须恢复训练配置，否则 mAP 虚高/虚低（实测 0.857→0.845 修正） |
