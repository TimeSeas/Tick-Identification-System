1、做数据划分，为什么不一次性将数据集放进去做识别
    在173 物种 里82 个物种不足 10 张，其中不少只有 1-3 张，细粒度分类的经验底线是每类至少 30-50 张才能学到稳定特征。
    在8055 张里混着多虫图、非蜱图、模糊图。没有清洗
    可以做分阶段处理
        类别规模 vs 精度曲线（3/31/173 三档对比）
    <10 张的物种做不了监督训练，但适合做零样本/检索实验
    用"31 类训练 + BioCLIP 检索识别长尾种"可以做一节"监督+零样本混合识别"的讨论章节。
2、做迁移学习为什么要替换神经网络的全连接层
    预训练模型（如ResNet50）原本是为ImageNet的1000类设计的，直接使用会报错，所以需要替换最后的全连接层。
    模型前面的卷积层已经学会了通用的图像特征（边缘、纹理、形状等），这些知识可以直接复用。
    替换掉原来的1000类分类器，换上适合你任务的小分类器，然后只训练这一小部分，大大减少训练时间和数据需求量。
3、为什么要做数据增强
    对每张图进行随机裁剪加随机缩放，让模型每一轮训练的时候，都是用不同的图，可以扩大数据量+防过拟合，让每一轮训练有意义

4、在做web对detect进行方法复用时为什么不直接传入图片路径进行解析
    如果传入的是图片路径，那么 detect内部就必须硬编码 Image.open()或 cv2.imread()，这意味着：
    只能处理本地文件系统路径；
    无法直接处理来自网络请求的二进制数据（如 UploadFile）；
    无法处理内存中的图像（如从数据库 blob 或缓存读取的数据）。
    而接收 np.ndarray后，调用方可以用任意方式获取图像数据（PIL、OpenCV、base64解码、ffmpeg等），只需最终输出一个形状为 (H, W, 3)的 RGB 数组即可。

6、什么是生命周期

@asynccontextmanager
async def lifespan(app: FastAPI):
    # yield 之前：应用启动时执行
    detector = Detector(...)
    classifier = SpeciesClassifier(...)
    app.state.pipeline = Pipeline(...)
    print("[启动] 模型加载完成，服务就绪")
    yield   # ← 应用正常运行，处理请求
    # yield 之后：应用关闭时执行
    print("[关闭] 服务停止")

    生命周期是一个应用从启动到关闭的过程，
    启动阶段（yield 前）：加载所有模型（Detector、Classifier、Pipeline），存入 app.state，使其常驻内存。这些操作只执行一次，后续请求直接复用已加载的模型，避免每次请求都重新加载。
    运行阶段（yield 处）：应用开始接收并处理请求，此时生命周期函数暂停等待，直到应用收到关闭信号。
    关闭阶段（yield 后）：执行清理工作（本例中仅打印日志，实际可释放 GPU 显存、关闭文件句柄等）。

7、如何在FastAPI接口中通过request.app.state访问生命周期中设置的pipeline对象，并调用其方法
    在 FastAPI 中，通过生命周期函数 lifespan将 Pipeline实例挂载到 app.state.pipeline后，任何路由处理函数都可以通过 request.app.state.pipeline访问这个全局唯一的实例，并调用其方法。


8、vite为什么要配置跨域与后端的CORS有什么不同
改 vite.config.ts，加：

server: {
  proxy: {
    '/api': 'http://localhost:8000'   // 前端所有 /api 请求转发到后端
  }
}
浏览器为了安全考虑，使用了同源策略
比如一个网页http://localhost:5173这个前端网页向另一个不同源（协议、域名、端口任一不同）的后端发送请求，浏览器会阻止读取响应
解决方法是在后端CORS，原理是后端在响应头加上 Access-Control-Allow-Origin，告诉浏览器，允许任何源读取数据
但是需要列出允许的源，白名单，不然风险太高，而且麻烦

还有种方法就是前端开发代理，原理是在开发阶段可以，利用Vite的开发服务器作为中间件，将请求转发给后端，后端响应，浏览器看着就是同一源
但是只有开发阶段可用，部署线上需要Nginx做反向代理

9、什么是反向代理
正向代理，是通过代理访问外部网络
反向代理，是外部客户端，先通过访问Nginx，Nginx再决定把请求交给哪个后端服务器处理

10、Vite Proxy和Nginx的区别
1、Nginx除了转发，还能缓存API响应，限制流量，增加安全头
2、并且性能更好，Nginx使用的是epoll事件驱动，而Vite Proxy是Node.js单线程
3、生命周期不同作为24小时的服务器，不像Vite Proxy只能在 npm run dev 运行时存在

11、epoll事件驱动的原理，Nginx如何实现高并发
传统服务器，Apache，每一个连接，都创建一个进程或线程，在等待数据库查询结果时就会阻塞
epoll通过实例在内核中对应一个 eventpoll对象包含红黑树，存储所有通过 epoll_ctl注册的文件描述符（fd）
就绪链表（rdllist）：一个双向链表，专门存放当前已经就绪的 epitem。
当你调用 epoll_ctl(EPOLL_CTL_ADD, fd, events)时，内核做两件事：

在红黑树中插入一个新的 epitem节点。

为该 fd 的等待队列（wait queue）注册一个回调函数，名为 ep_poll_callback。

当某个 fd 上有 I/O 事件发生（例如网卡收到数据，socket 变为可读），内核底层驱动会调用该 fd 的等待队列上注册的所有回调函数。
此时 ep_poll_callback被触发，它执行的操作是：

将对应的 epitem从红黑树中取出（或直接引用）并追加到就绪链表 rdllist 的尾部。

如果有进程正在 epoll_wait()上睡眠等待，则唤醒该进程。

1、接口（Interface）

2、 一个完整的vue文件需要什么，模版怎么写，为什么要这样写，怎么联调ts和发送请求、接收响应的
模版：
<script setup lang="ts">   ← ① 逻辑：数据、函数（TS 在这里）
</script>

<template>                ← ② 界面：HTML 结构（用 {{}} 和指令绑定数据）
</template>

<style scoped>           ← ③ 样式：只影响本文件的 CSS（scoped = 不污染别的页面）
</style>

2.1、为什么vue不像微信小程序那样，把JS、css拆分出来，而是写在一起
Vue基于虚拟DOM和JavaScript运行，.vue文件通过像Vite这样的构建工具编译成纯JS代码，模板和逻辑在同一JS上下文运行共享数据和方法
而微信小程序采用渲染层跑WXML、WXSS，逻辑层跑JS，通过Native层通信，JS无法操作DOM，通过setData传递数据给渲染层

2.2、发送请求到响应数据的全过程
阶段一：浏览器内（前端，TypeScript/Vue）

① 用户点击"开始分析"
- 文件：web/frontend/src/views/AnalyzeView.vue
- 模板里 @click="doAnalyze" → 执行 doAnalyze()（script 里）
- 此刻数据：file.value 里是用户刚才选的 File 对象（还在内存里，没上过网）

② 调用 API 层
- 文件：web/frontend/src/api/client.ts → analyzeImage(file)
- 这里发生第一次数据变形：File 对象 → FormData（form.append('file', file)）
- 为什么要变：HTTP 上传文件的标准格式就是 multipart/FormData，File 只是浏览器内存对象，不能直接发

③ axios 发出 HTTP 请求
- 同一文件：http.post('/analyze', form)
- 关键：没有写 http://localhost:8000，只写了 /api/v1/analyze——这就是分层的好处

④ Vite 代理拦截转发
- 文件：web/frontend/vite.config.ts 的 proxy: { '/api': 'http://localhost:8000' }
- 请求发出前，Vite 开发服务器看到 /api 开头 → 转发给后端 8000 端口
- 浏览器以为在和 5173 通信（同源、无跨域问题），实际是 Vite 在中间当"传话筒"

---

阶段二：后端处理（Python/FastAPI）

⑤ FastAPI 路由接单
- 文件：web/backend/app/main.py（include_router 注册过）→ web/backend/app/routers/analyze.py
- FastAPI 自动把 multipart 里的文件解析成 UploadFile 对象（file.content_type、await file.read() 得到图片字节 data）
- 校验：类型不是 image/* → 直接返回 {code:400}；超过 10MB → 同上（入口拦截）

⑥ 级联推理
- 文件：web/backend/app/services/pipeline.py → analyze(image_bytes)
- 数据变形链：
bytes → PIL Image → np.ndarray(H,W,3)        [pipeline.py 开头]
  → Detector.detect()                         [services/detector.py]
     ndarray → torch.Tensor(1,3,H,W) → 模型 → boxes/scores
     → [{"bbox":[...], "score":0.99}]        （这就是你的 detector 做的事）
  → 每个框：PIL crop 裁剪 → np.ndarray
  → SpeciesClassifier.classify()              [services/classifier.py]
     裁剪图 → 255 缩放 → 224 裁剪 → 归一化 tensor → ResNet → (slug, 置信度)
  → 阈值决策（读 thresholds.csv）→ confirmed / uncertain
  → risk_rules.advice_for()                   [services/risk_rules.py]
     slug 列表 → 风险文案
  → cn_map.get(slug)                          [utils/cn_map.py]
     slug → 中文名（对照表 CSV，lru_cache 只读一次盘）
- 产出：纯 Python dict（detections + risk_advice）

⑦ 可视化
- 文件：web/backend/app/utils/visualize.py → draw_result(data, detections)
- 数据变形：图片字节 + 检测结果 → PIL 画框画字 → JPEG 字节 → base64 字符串（带上 data:image/jpeg;base64, 前缀——专门为前端 <img> 准备的格式）

⑧ 打包返回
- 文件：web/backend/app/routers/analyze.py 最后
- result["result_image_base64"] = ...、result["request_id"] = ...
- return ok(result) → ok() 来自 web/backend/app/schemas.py → 包装成 {code:0, msg:"ok", data:result}
- FastAPI 自动序列化成 JSON 文本，经 HTTP 发回

---

阶段三：回程（前端接收）

⑨ axios 拦截器解包
- 文件：web/frontend/src/api/client.ts 的响应拦截器
- 网络层给 axios 的是原始 JSON 文本，axios 解析成 JS 对象 {code:200, msg:"ok", data:{...}}
- 拦截器检查 code === 200 → 把 data 抽出来直接返回（{code,msg} 壳子被剥掉）
- 所以 analyzeImage() 的返回值 = AnalyzeResult 对象，不再是响应包

⑩ 响应式更新，页面自动渲染
- 文件：回到 web/frontend/src/views/AnalyzeView.vue
- result.value = await analyzeImage(file.value) 一行赋值
- Vue 的响应式系统发现 result 变了 → 重新渲染模板里所有用它的地方：
  - v-if="result" 变 true → 结果区出现
  - <img :src="result.result_image_base64"> → base64 直接显示成图
  - v-for 循环 result.detections → 每个蜱虫一个标签
  - el-alert 显示 risk_advice
