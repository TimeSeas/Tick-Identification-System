1、做数据划分，为什么不一次性将数据集放进去做识别
    在173 物种 里82 个物种不足 10 张，其中不少只有 1-3 张，细粒度分类的经验底线是每类至少 30-50 张才能学到稳定特征。
    在8055 张里混着多虫图、非蜱图、模糊图。没有清洗
    可以做分阶段处理
        类别规模 vs 精度曲线（3/31/173 三档对比）
    <10 张的物种做不了监督训练，但适合做零样本/检索实验
    用"31 类训练 + BioCLIP 检索识别长尾种"可以做一节"监督+零样本混合识别"的讨论章节。
2、做迁移学习为什么要替换神经网络的全连接层
    预训练模型（如ResNet50）原本是为ImageNet的1000类设计的，直接使用会报错，所以需要替换最后的全连接层。
    模型前面的卷积层已经学会了通用的图像特征（边缘、纹理、形状等），这些知识可以直接复用。
    替换掉原来的1000类分类器，换上适合你任务的小分类器，然后只训练这一小部分，大大减少训练时间和数据需求量。
3、为什么要做数据增强
    对每张图进行随机裁剪加随机缩放，让模型每一轮训练的时候，都是用不同的图，可以扩大数据量+防过拟合，让每一轮训练有意义

4、在做web对detect进行方法复用时为什么不直接传入图片路径进行解析
    如果传入的是图片路径，那么 detect内部就必须硬编码 Image.open()或 cv2.imread()，这意味着：
    只能处理本地文件系统路径；
    无法直接处理来自网络请求的二进制数据（如 UploadFile）；
    无法处理内存中的图像（如从数据库 blob 或缓存读取的数据）。
    而接收 np.ndarray后，调用方可以用任意方式获取图像数据（PIL、OpenCV、base64解码、ffmpeg等），只需最终输出一个形状为 (H, W, 3)的 RGB 数组即可。

    router是一个 APIRouter实例
    @router.post("/classify")表示：当客户端向 /classify发送 POST 请求​ 时，调用下面的函数处理。

6、什么是生命周期

@asynccontextmanager
async def lifespan(app: FastAPI):
    # yield 之前：应用启动时执行
    detector = Detector(...)
    classifier = SpeciesClassifier(...)
    app.state.pipeline = Pipeline(...)
    print("[启动] 模型加载完成，服务就绪")
    yield   # ← 应用正常运行，处理请求
    # yield 之后：应用关闭时执行
    print("[关闭] 服务停止")

    生命周期是一个应用从启动到关闭的过程，
    启动阶段（yield 前）：加载所有模型（Detector、Classifier、Pipeline），存入 app.state，使其常驻内存。这些操作只执行一次，后续请求直接复用已加载的模型，避免每次请求都重新加载。
    运行阶段（yield 处）：应用开始接收并处理请求，此时生命周期函数暂停等待，直到应用收到关闭信号。
    关闭阶段（yield 后）：执行清理工作（本例中仅打印日志，实际可释放 GPU 显存、关闭文件句柄等）。

7、如何在FastAPI接口中通过request.app.state访问生命周期中设置的pipeline对象，并调用其方法
    在 FastAPI 中，通过生命周期函数 lifespan将 Pipeline实例挂载到 app.state.pipeline后，任何路由处理函数都可以通过 request.app.state.pipeline访问这个全局唯一的实例，并调用其方法。


8、vite为什么要配置跨域与后端的CORS有什么不同
改 vite.config.ts，加：

server: {
  proxy: {
    '/api': 'http://localhost:8000'   // 前端所有 /api 请求转发到后端
  }
}
浏览器为了安全考虑，使用了同源策略
比如一个网页http://localhost:5173这个前端网页向另一个不同源（协议、域名、端口任一不同）的后端发送请求，浏览器会阻止读取响应
解决方法是在后端CORS，原理是后端在响应头加上 Access-Control-Allow-Origin，告诉浏览器，允许任何源读取数据
但是需要列出允许的源，白名单，不然风险太高，而且麻烦

还有种方法就是前端开发代理，原理是在开发阶段可以，利用Vite的开发服务器作为中间件，将请求转发给后端，后端响应，浏览器看着就是同一源
但是只有开发阶段可用，部署线上需要Nginx做反向代理

9、什么是反向代理
正向代理，是通过代理访问外部网络
反向代理，是外部客户端，先通过访问Nginx，Nginx再决定把请求交给哪个后端服务器处理

10、Vite Proxy和Nginx的区别
1、Nginx除了转发，还能缓存API响应，限制流量，增加安全头
2、并且性能更好，Nginx使用的是epoll事件驱动，而Vite Proxy是Node.js单线程
3、生命周期不同作为24小时的服务器，不像Vite Proxy只能在 npm run dev 运行时存在

11、epoll事件驱动的原理，Nginx如何实现高并发
传统服务器，Apache，每一个连接，都创建一个进程或线程，在等待数据库查询结果时就会阻塞
epoll通过实例在内核中对应一个 eventpoll对象包含红黑树，存储所有通过 epoll_ctl注册的文件描述符（fd）
就绪链表（rdllist）：一个双向链表，专门存放当前已经就绪的 epitem。
当你调用 epoll_ctl(EPOLL_CTL_ADD, fd, events)时，内核做两件事：

在红黑树中插入一个新的 epitem节点。

为该 fd 的等待队列（wait queue）注册一个回调函数，名为 ep_poll_callback。

当某个 fd 上有 I/O 事件发生（例如网卡收到数据，socket 变为可读），内核底层驱动会调用该 fd 的等待队列上注册的所有回调函数。
此时 ep_poll_callback被触发，它执行的操作是：

将对应的 epitem从红黑树中取出（或直接引用）并追加到就绪链表 rdllist 的尾部。

如果有进程正在 epoll_wait()上睡眠等待，则唤醒该进程。
